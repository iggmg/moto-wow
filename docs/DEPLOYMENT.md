# Публикация

## Клиент на GitHub Pages

1. Выполнить `npm run build`, `node scripts/audit-public.js`, `node scripts/prepare-public.js`. Для нового публичного репозитория использовать `artifacts/public-source/`: это копия по списку разрешённых файлов без локальных журналов, аккаунтов и старой истории Git. Не загружать MAINBOTS целиком.
2. Отправить только проверенную копию в отдельный публичный `moto-wow`. Первый коммит создать с нейтральными именем и адресом автора, например Moto Rift / publisher@example.invalid. Не переносить существующую локальную историю.
3. Settings → Pages → Source: GitHub Actions.
4. Settings → Secrets and variables → Actions → Variables: `VITE_API_URL` = полный HTTPS-адрес игрового сервера. Это публичный адрес, не секрет.
5. Workflow `Verify and publish browser game` выполняет проверки, собирает клиент и публикует dist.
6. Если сервер ещё не выбран, оставить VITE_API_URL пустой: тренировки работают, онлайн отмечен как недоступный.

Клиент использует относительные пути к JS/CSS/GLB, поэтому работает в подкаталоге GitHub Pages. Доступный URL нужно получить из результата Actions; его нельзя угадать до создания репозитория.

## Сервер

Node 24, один процесс, постоянный диск для SQLite. Можно использовать отдельный VPS с Docker либо сервис контейнерного хостинга с WebSocket и постоянным диском. Бесплатные засыпающие инстансы и временная файловая система не подходят для стабильных заездов/сохранения аккаунтов.

Для VPS:

```sh
PUBLIC_ORIGIN=https://YOUR-ACCOUNT.github.io docker compose up -d --build
```

PUBLIC_ORIGIN — точный origin (схема + домен, без пути репозитория). Контейнер слушает только localhost хоста на 8787, наружу — через HTTPS reverse proxy. Настройте домен сервера, TLS и проксирование WebSocket. Пример Nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 90s;
}
```

Здесь предполагается отдельный TLS virtual host; сертификат и домен настраиваются в выбранной инфраструктуре. Не вставляйте игровой location в конфиг действующего бот-сервиса.

## Проверка публикации

- `GET /api/health` отвечает ok/version текущих правил по HTTPS.
- Создать два аккаунта из двух независимых браузеров на реальном Pages URL.
- Войти с одинаковым кодом комнаты, увидеть друг друга в движении.
- Пройти все 16 точек и финиш: запись появилась в онлайн-рекордах и сохранилась после перезапуска сервера.
- Завершить сессию; старый токен больше не действует.
- Вручную проверить WebGL 2 и кнопки управления на физическом телефоне.

## Резервное копирование

Резервировать базу через SQLite backup API или остановленный контейнер/согласованный snapshot тома; нельзя копировать один sqlite-файл активной WAL-базы без учёта WAL. Пример Node.js 24:

```js
import { DatabaseSync, backup } from 'node:sqlite';
const database = new DatabaseSync('/data/moto-wow.sqlite');
await backup(database, '/backups/moto-wow-YYYY-MM-DD.sqlite');
database.close();
```

Резервные копии содержат аккаунты; хранить приватно и проверять восстановление. Перед обновлением сохранять текущий образ/коммит и согласованную копию базы. Откат: предыдущий образ и при необходимости проверенная копия SQLite.

## Railway: первый онлайн-сервер

Один контейнер из `iggmg/moto-wow`, Dockerfile, без serverless/sleep и без дополнительных replicas. Регион Singapore для первой проверки. Настройки нового сервиса задаются в панели Railway: healthcheck `/api/health`, timeout 120 секунд, restart On Failure с максимумом 3 попытки. Config as Code для новых сервисов недоступен с 28.08.2026. Постоянный volume 0.5 GB монтировать в `/data` **до** первого запуска регистрации.

Переменные:

```text
PUBLIC_ORIGIN=https://iggmg.github.io
DATABASE_PATH=/data/moto-wow.sqlite
BACKUP_DIRECTORY=/data/backups
COOKIE_SECURE=1
TRUST_RAILWAY_PROXY=1
RAILWAY_RUN_UID=0
```

Railway создаёт volume от root. `server/launch.js` назначает владельцем `/data` пользователя node (UID/GID 1000) и сбрасывает права root до импорта игрового сервера. На VPS/Docker по умолчанию остаётся `USER node`. `TRUST_RAILWAY_PROXY` включать только за Railway HTTPS edge: он выставляет `X-Real-IP`; вне Railway заголовок по умолчанию игнорируется. Не открывать прямой TCP-доступ к серверу.

Согласованные SQLite-копии создаются на старте и ежедневно, проверяются `integrity_check`, права 0600, последние семь копий. Они находятся на том же томе и защищают от ошибок обновления, но не от потери самого тома. Railway Volume Backups доступны только на Pro; в текущем Trial отдельные снимки не включены. Для независимой копии потребуется внешнее приватное хранилище либо отдельное согласование Pro, затем проверка восстановления. Перед обновлением базы дополнительно сохранить проверенную копию за пределами работающего тома. Не публиковать базу или бэкапы в GitHub.

После проверки HTTPS-домена сервера задать Actions variable `VITE_API_URL` и заново запустить Pages workflow. Проверить регистрацию, вход, двух игроков, синхронный старт, logout, сохранение после рестарта, отказы для постороннего Origin и поддельных результатов. Бесплатный trial ограничен остатком кредита/сроком; платный тариф автоматически не подключать.
