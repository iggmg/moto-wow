# Архитектура

## Выбор технологий

Нет универсального «самого лучшего» стека. Для одной браузерной 3D-трассы и небольших комнат выбран компактный набор широко используемых технологий: Three.js для рендера, glTF/GLB для переносимых моделей, Vite для статического клиента, WebSocket для realtime, Node/SQLite для одного небольшого постоянного сервера. React/полный игровой редактор здесь добавили бы слои без необходимости.

Физика — собственная детерминированная аркадная модель: продольный разгон/торможение, управляемость, сцепление покрытия, высота земли, препятствия и штрафы. Это не полноценная многотельная физика мотоцикла. Для падений, сложных прыжков и контактов подвески следующая итерация должна использовать Rapier и отдельно настроенную двухколёсную модель, с проверкой производительности WebAssembly.

## Поток данных

Клавиатура/касание → нормализованные input → локальный fixed-step прогноз → WebSocket → authoritative fixed-step сервера → снимки состояния → reconciliation своего мотоцикла / сглаживание остальных.

Сервер считает круги только из собственной симуляции и последовательности 16 точек. API отправки готового результата не существует. Комната живёт, пока в ней есть игроки. Онлайн-сессия нужна для выдачи одноразового WebSocket-билета; билет короткоживущий и потребляется один раз. Аккаунт может находиться в комнате только одним экземпляром; вход в новой вкладке заменяет старый.

SQLite: users, sessions, laps. Пароль scrypt с солью; в базе хранится SHA-256 opaque-токена сессии. На одном origin используется HttpOnly cookie. Для frontend на другом origin ответ входа содержит токен, который клиент держит только в оперативной памяти; при запрете сторонних cookie после перезагрузки потребуется снова войти. Токены/пароли не записываются в localStorage.

## Производительность

Повторяющиеся деревья используют InstancedMesh; геометрия мотоциклов объединяется по материалам, при этом колёса сохраняют собственные узлы. Ограничена плотность пикселей. В гараже фон рисуется реже, просмотр модели максимум 30 FPS. Низкая частота кадров в самом заезде автоматически снижает плотность пикселей до 1; тени сохраняются. Меню, которое намеренно рисуется реже, не влияет на качество заезда. Движение считается фиксированными шагами с ограниченным catch-up; вкладка, оставленная в фоне, не является источником онлайн-времени.

## Проверенные первоисточники

- [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html): glTF 2.0, mesh compression и расширения.
- [Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html): уменьшение draw calls для повторяющейся геометрии.
- [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site): статическая публикация, отдельный backend.
- [Node SQLite](https://nodejs.org/api/sqlite.html): встроенная база, SQL prepared statements и backup.
- [Node crypto](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback): scrypt.
- [ws](https://github.com/websockets/ws): WebSocket сервер, upgrade и heartbeat.

## Пределы первой версии

Восемь участников на комнату — программный предел, не доказанная максимальная вместимость сервера. Нагрузочный тест ещё нужен. Нет глобальной миграции/распределения комнат, email-восстановления, общего старта гонки или комплексной защиты от ботов. Мир вдохновлён фэнтези, с собственными персонажами и моделями. Модели оригинальные и приближённые; требование фотореализма/точной заводской формы пока не доказано.

## Графика и звук: обновление 2026-10-07

Ветвистые деревья, листва, папоротники, трава и камни используют инстансинг; неподвижные элементы руин и ограждений объединяются по материалам. Корректно настроена матрица теневой камеры; область теней следует за игроком. Сухой гравий и грязь используют отдельные PBR-материалы, на дороге есть поперечные сегменты, колеи и неровные края. Текстуры включены локально с реестром происхождения.

Геометрия мотоциклов объединяется и индексируется с сохранением нормалей и UV. В первой редакции GLB с райдером около 1,4–1,5 МБ на мотоцикл (в новой — 1,8–2,0 МБ). Отдельные узлы BikeBody, Rider и WheelRear/WheelFront сохранены.

Звук Web Audio активируется в обработчике старта: гармоники четырёхтактного двигателя, механические призвуки, шум шин по типу поверхности, ветер и импульс столкновения. Выключатель сохраняет выбор в браузере. Автотест проверяет состояние AudioContext running и ненулевой RMS сигнала. Акустика конкретного устройства и системная громкость этим тестом не проверяются.

## Преследование орками

Каждый орк хранит позицию, курс, цель и состояние patrol/chase/attack/return. В тренировке AI обновляется вместе с физикой 60 раз в секунду, в комнате — один раз за серверный шаг для всех игроков. Ближайшая доступная цель выбирается при обнаружении; текущая сохраняется до потери дистанции 100 м, выхода орка за радиус 110 м от патруля или отключения игрока. Радиус обнаружения: 90 м для скорости ниже 1 м/с и 36 м для движущегося гонщика. Скорость погони 6,5 м/с. Удар при дистанции менее 1,4 м использует обычный штраф +2 с и 1,8 с защиты от повторного контакта; восстановление после замаха 1,2 с позволяет уехать даже на медленном мотоцикле.

Версия протокола 3: снимки комнаты включают общий массив orcs. Клиент использует эти позиции для прогноза столкновений и сглаживает их при отрисовке; цель и движение орков определяет сервер. В тренировке используется тот же AI. Анимация рук/ног остаётся отдельной от статических частей модели после объединения геометрии.

## Версия 4: погода, прыжки и дальние атаки

shared/game.js содержит геометрию двух трамплинов, двух речных русел, покрытий и погоды. groundHeight применяется и в рендере, и в физике: подъём трамплина не является только картинкой. Выезд вперёд при скорости >5 м/с задаёт вертикальную скорость и airborne; гравитация 9,81 м/с² возвращает мотоцикл на землю, в воздухе ослаблен поворот. Вода/песок/снег меняют разгон, сопротивление и максимальную скорость; дождь уменьшает grip.

shared/combat.js хранит общий массив физических снарядов. Орки чередуют стрелы, копья и камни; замах 0,65 с, ограниченные дальность/скорость/время жизни, баллистическая вертикальная скорость и swept collision. Снаряд может промахнуться, попадание даёт +2 с и замедление. AI и снаряды обрабатываются один раз за серверный шаг перед движением и проверкой финиша. Подмена состояния снарядов/погоды клиентскими сообщениями игнорируется.

Снимки версии 4 включают weather и combat. Погоду задаёт первый участник новой комнаты; последующие участники используют её. Онлайн-клиент прогнозирует своё движение и получает дальние попадания от сервера. Тренировка считает ту же логику локально. Дождь/снег рисуются одним набором линий/точек, снег покрывает наклонённые вверх поверхности, вода имеет движущиеся волны и мягкие края.

Импортированные орки используют SkeletonUtils.clone, отдельный AnimationMixer на персонажа и исходные клипы. Процедурная модель остаётся резервной при ошибке загрузки. Материалы/геометрия мотоциклов объединяются по материалам с сохранением колёс и райдера; GLB теперь около 1,8–2,0 МБ. Формы и раскраски сверены с пользовательскими фотографиями, точность заводской геометрии не заявлена.
